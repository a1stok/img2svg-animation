# Committing Rules

When writing commit messages in this project, you must strictly follow these rules:

- **Plain English**: Write commit messages in clear, plain English.
- **No Emojis**: Do not use emojis anywhere in the commit message.
- **No Conventional Commits**: Do NOT use prefixes like "feat:", "fix:", "chore:", "refactor:", etc.
- **Reference Issues**: If the commit addresses a specific GitHub sub-issue or PRD, reference the issue number in the commit message (e.g., `(fixes #2)`).
- **No Micro-Commits**: Do not commit tiny, iterative micro-changes independently. Only commit when an entire issue or logical feature milestone is fully complete.
- **Focused Commits**: Do not bundle multiple unconnected changes into a single massive commit. Make one focused commit that addresses the specific task or sub-issue.
